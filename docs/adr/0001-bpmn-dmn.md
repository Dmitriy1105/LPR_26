# ADR 0001 — BPMN and DMN as process sources
Status: accepted architectural direction; implementation pending.
BPMN 2.0 describes control flow; DMN 1.3 describes decision tables. Keep Alpha 1 unchanged. XML is authoritative; do not duplicate scenario branching in JavaScript. Initial models are descriptive, not executable-certified. The first model has a revision loop; runtime must bound iterations and reject unresolved conditions. Unauthorized actors must never emit a valid approve/reject event: DMN deny outcome routes to a separate blocked end event, not a business rejection by that actor. Bind businessRuleTask decide to approval_outcome via explicit adapter configuration. Use a standards-aware parser and FEEL evaluator; no eval. Validate XML against official schemas, references, gateway exclusivity, reachability, termination and all boolean DMN combinations. Add BPMN DI for visual editing. Keep organizational grants, relationship graph and source evidence separate. No CRM export or NLP changes in this stage.
